# Agent Note: 通过 DSH provider 分发带版本的需求

Status: implemented

[English](2026-11-04-requirement-dispatch.md) | 中文

## Problem

用户需要在单次会话之外保存需求，并将实现工作交给不同的编码 agent。仅有可变的任务描述无法确定外部 agent 实现了哪个版本，也无法区分执行完成与用户验收。

## Decision

独立 bundle 使用 SQLite 保存需求和分发尝试。每次编辑递增内容版本；分发原子领取指定版本，并通过数据库约束保证不同连接中每条需求最多有一个活动尝试。委派提示词携带完整快照。Agent 执行完成更新分发结果，需求验收仍由用户显式执行。

单轮执行使用 DSH 子代理注册表。持久路由通过受管子进程调用原生 Codex、Pi 和 OpenCode CLI。需求插件卸载后，仍可恢复它们保存的会话。SQLite 把已确认的原生线程 ID 和工作目录绑定到分发尝试。续接只能选择同一需求下的历史分发，调用方不能直接指定无关的原生线程。插件卸载先取消并等待分发，再关闭 SQLite。

## Alternatives considered

**恢复最近一次原生会话。** 不同任务可能共享账号和工作目录。使用保存的精确线程 ID，可以在同目录有其他分发时仍找回原会话。线程缺失或不匹配时，本次尝试失败，不创建替代会话。

**执行结束便将需求设为完成。** Agent 的最终答复不构成用户验收。分发和需求分别记录状态，保留这一差异并支持检查实现。

**自动重试持久化的进行中尝试。** 宿主失败后，外部进程可能仍在工作，也可能已提交修改。保留占用能避免重复执行；人工恢复需要未来的显式协议。

## Consequences

其他已安装的 provider 可以提供单轮路由。恢复 Codex 会话需要访问原生账号、会话存储和工作目录。未保存线程的历史分发仍可读取，但不能恢复。无密钥测试检查原工作目录和线程身份，使用真实 Codex 和 OpenCode 的验证覆盖在新 CLI 进程中恢复第一轮上下文。
